1. EXECUTIVE SUMMARY & OBJECTIVE
================================================================================
The objective of this project is to upgrade the existing Gift History functionality
in Invitation Hub into a dual-mode "Gift Received" and "Gift Given" ledger system,
while strictly adhering to the existing UI styling, theme, colors, navigation bar,
typography, spacing, authentication, and multi-tenant isolation rules.

Key Requirements:
1. Reorganize Gift History Header:
   - Move heading upward to eliminate wasted screen space.
   - Insert a 2-option segmented selector immediately below the heading:
     Option 1: Gift Received (Default)
     Option 2: Gift Given
   - Switching between options updates the displayed ledger smoothly without
     navigating away.
   - Preserve existing search input and category filter pills (All Gifts, Gold,
     Silver, Cash, Electronics, Other).

2. Gift Received Continuity:
   - Preserve all existing records from the database (past family functions).
   - Display gift name, category, estimated value (INR), notes, and linked event info.
   - Do not display gifts given in this section.

3. Gift Given Flow:
   - Display a prominent "+" button at the top-right of the content area when
     Gift Given is active.
   - Restrict button visibility to admin (VIP) and permitted users.
   - Step 1 (Event Selection): Clicking "+" opens an event selector dialog/sheet
     listing saved events (invitations & functions) with name, host, date, place.
     Prioritizes and highlights ended/past events.
   - Step 2 (Gift Entry Form): Reuses the exact form layout and fields shown in
     the existing Gift Received form:
       - Gift Name/Description (Label: "Gift Given", placeholder: "Enter gift")
       - Gift Category dropdown
       - Estimated Value (INR) numeric input
       - Notes textarea
       - Selected event info header (so the user knows the function context)
       - Cancel and Save Record buttons
   - Step 3 (Save & Validation): Prevent duplicate submission on rapid clicks,
     validate inputs, persist to database with tenant/VIP account ID, update UI
     optimistically and show success notification.

4. Link to Event Page & Lifecycle Continuity:
   - Every Gift Given record links to the permanent event ID.
   - When an event moves from Upcoming to Past based on calendar date passage
     (isInvitationPastByDate), the event ID remains identical and gift records
     remain permanently associated.
   - Display a "Gifts Given" section on the Event Detail screen (/event/:id)
     for the specific event with proper permission checks.

5. Database & Multi-Tenant Security:
   - Introduce public.gift_records table via a safe migration.
   - Apply Row Level Security (RLS) policies scoped strictly via get_auth_vip_id().
   - Add performance indexes on vip_id, event_id, direction, and event_date.
   - Support both remote Supabase persistence and offline local storage.

3. DATABASE SCHEMA & SUPABASE MIGRATION
================================================================================
Create a new migration file:
supabase/migrations/20261011_add_gift_records.sql

SQL Specification:
--------------------------------------------------------------------------------
CREATE TABLE IF NOT EXISTS public.gift_records (
    id TEXT PRIMARY KEY,
    vip_id TEXT NOT NULL,
    direction TEXT NOT NULL DEFAULT 'given' CHECK (direction IN ('received', 'given')),
    event_id TEXT NOT NULL,
    event_title TEXT NOT NULL,
    event_date DATE NOT NULL,
    event_type TEXT,
    event_venue TEXT,
    recipient_name TEXT,
    recipient_person_id TEXT REFERENCES public.people(id) ON DELETE SET NULL,
    gift_name TEXT NOT NULL,
    gift_category TEXT NOT NULL DEFAULT 'other',
    estimated_value NUMERIC,
    notes TEXT,
    created_by TEXT DEFAULT 'vip',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Fast lookup indexes
CREATE INDEX IF NOT EXISTS idx_gift_records_vip_id ON public.gift_records(vip_id);
CREATE INDEX IF NOT EXISTS idx_gift_records_event_id ON public.gift_records(event_id);
CREATE INDEX IF NOT EXISTS idx_gift_records_direction ON public.gift_records(direction);
CREATE INDEX IF NOT EXISTS idx_gift_records_date ON public.gift_records(event_date DESC);

-- Enable Row Level Security (RLS)
ALTER TABLE public.gift_records ENABLE ROW LEVEL SECURITY;

-- Grant API permissions
GRANT ALL ON TABLE public.gift_records TO anon, authenticated, service_role;

-- Tenant isolation RLS policies using existing get_auth_vip_id() helper
CREATE POLICY "gift_records_isolated_select"
    ON public.gift_records FOR SELECT TO anon, authenticated
    USING (vip_id = public.get_auth_vip_id());

CREATE POLICY "gift_records_isolated_insert"
    ON public.gift_records FOR INSERT TO anon, authenticated
    WITH CHECK (vip_id = public.get_auth_vip_id());

CREATE POLICY "gift_records_isolated_update"
    ON public.gift_records FOR UPDATE TO anon, authenticated
    USING (vip_id = public.get_auth_vip_id())
    WITH CHECK (vip_id = public.get_auth_vip_id());

CREATE POLICY "gift_records_isolated_delete"
    ON public.gift_records FOR DELETE TO anon, authenticated
    USING (vip_id = public.get_auth_vip_id());
--------------------------------------------------------------------------------

Step 1: GiftHistoryScreen Layout Refinement
--------------------------------------------------------------------------------
- Reduce vertical header padding.
- Place Back button, Heading ("Gift History"), and (if in Given mode) "+ Record Gift"
  button on the top line.
- Render high-contrast Segmented Control:
  [ Gift Received ]  [ Gift Given ]
  - Default: 'received'

- Preserved Search Bar & Category Filter Pills:
  - Input: "Search gifts such as gold, silver, etc..."
  - Categories: All Gifts, Gold, Silver, Cash, Electronics, Other
- Content Rendering:
  - When 'received' is active:
    Displays gifts received from familyEvents (+ any received records in gift_records).
    Preserves recipient card, badge, category, valuation, notes, and navigation to person.
  - When 'given' is active:

Step 2: Event Selection Dialog / Modal (SelectEventModal)
--------------------------------------------------------------------------------
- Opened when authorized user taps "+" / "Record Gift" in Gift Given mode.
- Collects saved events from store (invitations and familyEvents).
- Organizes events:
  - Section 1: "Past Functions & Events Attended" (Ended/past dates prioritized).
  - Section 2: "Upcoming Invitations & Events".
- Displays for each event:
  - Title (e.g., "Rajesh & Meera Wedding")
  - Host / Main person
  - Formatted date
  - Venue / Location
  - Status badge (e.g., "Ended", "Upcoming")
- Search bar to filter events quickly by name or host.
- Empty state if no events exist: "No saved events found. Please add an invitation first."
- Tapping an event selects it and opens the Gift Given Entry Form with the event
  pre-selected.

Step 3: Gift Given Entry Form (AddGiftGivenModal)
--------------------------------------------------------------------------------
- Replicates the exact layout from Screenshot 2:
  1. Selected Event Header Card:
     Displays Event Name, Host, Date, and Venue in a compact summary card so
     the user has clear context.
  2. Input: "Gift Given" (placeholder: "Enter gift")
  3. Two-Column Grid:
     - Left: "Gift Category" (select dropdown with standard categories)
     - Right: "Estimated Value (₹)" (numeric input, placeholder: "Enter gift value")
  4. Textarea: "Notes" (placeholder: "Enter notes here...", rows: 3)

  6. Action Buttons:

- Validation & Safety:

  - Linked gift records remain associated with the event and display properly

6. AUTHORIZATION & ACCESS CONTROL
================================================================================
- Admin (isVIP === true):
  - Can view Gift Received and Gift Given.
  - Can see "+" button and record given gifts.
  - Can edit and delete records.
- Delegated Staff User:
  - Viewing Gift History: checked via permissions.canViewGiftHistory !== false.
  - Adding / Editing Given Gifts: checked via permissions.canEditEvents !== false
    or permissions.canViewGiftHistory !== false.
- Unauthorized Users:
  - "+" button is hidden in UI.
  - Database calls rejected via Supabase RLS policies.
